# UI Internationalization (i18n)

The MC web UI is internationalized with [next-intl](https://next-intl.dev)
(English default, German shipped). This covers the **web interface only** —
two things it deliberately does *not* cover:

- **Agent response language** is a per-agent setting (`agents.language`),
  rendered into the SOUL template as a respond-in-that-language instruction.
- **Agent templates** (SOUL/CARD/TOOLS) stay English — they are model
  instructions, not UI copy.

## Architecture

- **Cookie-based, no locale in the URL.** MC is an app behind a login;
  `/agents` stays `/agents` in every language. The active locale comes from
  the `NEXT_LOCALE` cookie (`src/i18n/request.ts`); the selector in
  **Settings → Profile → Language** writes the cookie and calls
  `router.refresh()`, so the change applies immediately.
- **Catalogs** live in `frontend-v2/messages/<locale>.json`, namespaced
  (`nav`, `settingsProfile`, …). `en.json` is the reference catalog — every
  key must exist there.
- The plugin is wired in `next.config.ts` (`createNextIntlPlugin`), the
  provider in `src/app/layout.tsx` (which also sets `<html lang>`).

## Adding / translating strings

Client components:

```tsx
import { useTranslations } from "next-intl";

const t = useTranslations("myNamespace");
<span>{t("myKey")}</span>
```

Shared constants (see `Sidebar.tsx` for the pattern): store a `labelKey`
in the constant, translate at the render site — never store translated
strings in module-level constants (they would freeze in one language).

Add the key to **both** `messages/en.json` and `messages/de.json`.

## Adding a locale

1. Create `messages/<locale>.json` (copy `en.json`, translate).
2. Add the locale to `LOCALES` in `src/i18n/request.ts`.
3. Add an `<option>` to the language selector in Settings → Profile.

## Tests

`src/test-setup.ts` mocks next-intl globally and resolves keys against the
**real** `messages/en.json` — tests assert actual English labels without
mounting a provider. A key missing from the catalog resolves to the key
itself, so a label assertion fails loudly instead of passing on a phantom
string.

## Migration status

The infrastructure plus pattern pages (navigation, Settings → Profile)
landed first; the remaining pages are being migrated incrementally.
**New UI code must use `t()` from the start** — no new hardcoded UI strings.
