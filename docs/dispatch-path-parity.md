# Dispatch Path Parity — poll.sh vs. Bridge (native) vs. Bridge (ACP)

Status: inventory, no fixes (scope rule: fix cards are cut from this table, one per gap).
Baseline: `main` @ b1213992 (PR #498 sinks wiring NOT merged — the ACP sink rows below document the main state).
Date: 2026-09-12.

## How to read this table

Three delivery paths drive the same backend:

- **poll.sh** — tmux screen-scrape loop in `docker/shared/poll.sh` (+ `docker/mc-agent-base/`, `docker/mc-claude-agent/` images). Claim/delivery/lifecycle glue in `backend/app/routers/agents.py` (`/agent/me/poll`).
- **Bridge native** — `docker/omp-bridge/bridge.py` `serve_loop` with `OMP_DRIVER != acp`: injects the dispatch into the persistent omp TUI (tmux window 0) and reads the turn-end hook signal file.
- **Bridge ACP** — same `serve_loop` with `OMP_DRIVER=acp`: drives a headless `omp acp` session through `run_acp_once` instead of the TUI.

Legend: **yes** = mechanism present · **no** = absent on this path (gap) · **different** = present, but behaves differently.
"Backend side" rows are shared by all three paths and listed only where the *path-side* half differs.

## Gap summary (fix-card candidates)

| Gap | Rows | Owner path | Incident form |
|-----|------|-----------|---------------|
| G1: Comment-cursor can stay missing → heartbeat soft-interrupt on agent's own comments | 3 | backend (cursor coupled to `/me/poll` only; any low-polling path exposes it; first seen on ACP) | Heartbeat aborts the agent's turn every ~26 s with "ungelesene blocker/handoff-Nachrichten" although the only unread comments are the agent's own — turn restarts in a loop, task makes no progress. |
| G2: No startup recovery in serve_loop — **CLOSED** (card f5cc4cee point e, `fix/acp-unblock-and-startup-recovery`) | 7 | bridge (native + ACP) | Was: Docker restart during an active card → agent idles next to its in_progress card; prompt re-delivery waited for the backend orphan threshold instead of the immediate `active-task-recovery` re-paste poll.sh does. | G3: ACP transcript/preview/usage missing on main | 13, 14, 15 | bridge ACP (PR #498 open) | Sessions page shows no transcript/preview for ACP runs; cost/usage stays unharvested; orphan liveness loses the model-usage signal. |
| G4: ACP idle watchdog blind to non-tool progress | 11 | bridge ACP | Long reasoning stretch without tool calls → watchdog kills a healthy run → task ends blocked ("abort_hang") although the model was producing. |

- Rows marked "Backend side: shared" behave identically for all three paths by construction (same endpoint); the gaps live in the path-side half.
- Baseline: rebased on `main` @ 1aafe630 (#514). 1aafe630 touches none of the audited files — all `file:line` anchors re-verified against b1213992..1aafe630 (empty diff on the audited set). - The `_make_acp_run_factory` interrupt_state forwarding guard (`_RUN_ACP_ACCEPTS_INTERRUPT_STATE`) exists only on the PR #498 branch, not on main.
- Part 2 wiring test: `docker/omp-bridge/tests/test_dispatch_path_parity.py` — registry is checked in BOTH directions (forward: every entry exists and serve_loop wires it; reverse: a new `run_*(_once|_turn|_continue)` factory or a new `OMP_DRIVER` branch fails the suite until it joins the table), and the G3 tripwire reads every `run_acp_once` call site via AST (keywords survive nested parens).
