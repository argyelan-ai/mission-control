# Dispatch Path Parity — poll.sh vs. Bridge (native) vs. Bridge (ACP)

Status: inventory, no fixes (scope rule: fix cards are cut from this table, one per gap).
Baseline: `main` @ 314c57f (#530). Re-anchored after #498 (ACP sinks + M8), #522 (parked-resume rotation + startup recovery) and #523 (G4 watchdog) all merged.
Date: 2026-09-12.

## How to read this table

Three delivery paths drive the same backend:

- **poll.sh** — tmux screen-scrape loop in `docker/shared/poll.sh` (+ `docker/mc-agent-base/`, `docker/mc-claude-agent/` images). Claim/delivery/lifecycle glue in `backend/app/routers/agents.py` (`/agent/me/poll`).
- **Bridge native** — `docker/omp-bridge/bridge.py` `serve_loop` (bridge.py:2405-2897) with `OMP_DRIVER != acp`: injects the dispatch into the persistent omp TUI (tmux window 0) and reads the turn-end hook signal file.
- **Bridge ACP** — same `serve_loop` with `OMP_DRIVER=acp`: drives a headless `omp acp` session through `_make_acp_run_factory` → `run_acp_once` instead of the TUI.

Legend: **yes** = mechanism present · **no** = absent on this path (gap) · **different** = present, but behaves differently.
"Backend side" rows are shared by all three paths and listed only where the *path-side* half differs.

Every `file:line` below was re-measured against 314c57f for this revision; the previous revision's anchors (baseline b1213992/1aafe630) are stale and were replaced, not carried over.

## Notes

- Rows marked "shared" behave identically for all three paths by construction (same endpoint or same code above the driver branch); the gaps live in the path-side half.
- **Baseline moved twice during this audit.** The previous revision anchored on b1213992 (later 1aafe630). This revision re-measures every anchor on 314c57f, after #498, #522, #523 and #530 landed. Anchors were re-derived from the file, not shifted by a diff offset.
- The card that commissioned this refresh assumed G1 (#519) had landed. It has not: `gh pr view 519` → OPEN, and the main-side evidence (single `_upsert_cursor` caller, no migration 0197, no author filter in `soft_unread`) is unchanged. Row 3 and the G1 summary row stay "open".
- `run_omp_subprocess` (bridge.py) is the legacy ADR-045 headless one-shot behind `--run`/`--replay`, not one of the three audited serve_loop paths — deliberately outside the table; the parity test's `PATH_DEF_RE` documents this exclusion.
- Since #498 the ACP branch reaches `run_acp_once` ONLY through `_make_acp_run_factory`; `test_serve_loop_wiring.py::test_no_bare_run_acp_once_call_in_serve_loop` pins that. The parity test's own G3 tripwire was rewritten accordingly (it used to require a bare call site inside serve_loop and went red on the #498 merge).
- **Substring pins are not enough — found by this card's own sabotage probe.** Two probes (removing the `_stream_heartbeat()` call, unwiring `_make_http_recovery`) initially stayed GREEN: a deleted CALL leaves the `def` behind, and `recovery_fn` is a prefix of `recovery_fn2`. The closed-gap pins are therefore call-based (AST) since this revision, and the probes are re-run in the task record to show them red. Anyone extending `SERVE_LOOP_WIRING` should assume the same trap.
- Part 2 wiring test: `docker/omp-bridge/tests/test_dispatch_path_parity.py` — the registry is checked in BOTH directions (forward: every entry exists and serve_loop wires it; reverse: a new `run_*(_once|_turn|_continue)` factory or a new `OMP_DRIVER` branch fails the suite until it joins the table), the closed gaps G2/G3/G4 are now POSITIVE assertions rather than exceptions, and M7 is pinned per factory call site.
- **Accepted parity, not a gap (review #522 W1):** `GET /me/active-task-recovery` (agents.py:3337) filters `status.in_(["in_progress", "blocked", "review"])`, so a bridge restart while a card sits `blocked` can also come back as a fresh `new_task` dispatch. poll.sh's `recover_task()` has the same filter and always has (row 7) — the bridge-side recovery inherits behavior poll.sh already exhibits rather than introducing a new one. Narrowing it would be a behavior change to a shared endpoint, outside this card's scope.
