# docs/produkt — product map, rules, known gaps

Checked by the coherence tool `kz` (config: [`.kohaerenz.yaml`](../../.kohaerenz.yaml), stage 1).
It keeps what MC offers (journeys, features), its rules and the code from drifting apart.

| File | What | Who edits |
|---|---|---|
| `landkarte.yaml` | Journeys (what the operator gets done) and features (pages, later endpoints and tables) with a status | by hand, in the PR that changes the feature |
| `regeln.yaml` | Rules with their guard test, rejected ideas, code declared dead | by hand, in the PR that adds or changes a guard |
| `inventar.json` | Pages, endpoints and tables read from the code | generated: `kz inventory --write` |
| `luecken-basis.json` | Known gaps (the ratchet). May only shrink | generated: `kz check --update-baseline` |

The endpoints come from `backend/openapi.json`, generated by
`cd backend && python scripts/export_openapi.py` and kept fresh by
`backend/tests/test_openapi_export.py`.

## Run it

```sh
kz check          # all checks; only NEW gaps fail, known ones are listed
kz links          # dead paths in AGENTS.md / CLAUDE.md
kz brief --paths <paths> --text "<job>"   # context before a job
```

- Added a page, endpoint or table? Put it into a feature in `landkarte.yaml` (or `internal`),
  then `kz inventory --write`.
- Fixed a known gap? `kz check --update-baseline` removes it from the ratchet.
- A new gap cannot be added to the baseline without `--allow-grow` — fix it instead.
  Growing the baseline needs the operator's OK in the PR.

## Rules for entries

- English, no names, hosts, addresses or usage numbers (public repository).
- A status comes from a doc: name it in `source` (ADR, PRINCIPLES, ROADMAP). `note: unconfirmed`
  marks a page whose status no doc states yet.
- An `active` rule needs an existing guard test (`path::test_name`), otherwise it is a `wish`.
  Anchor the guarded code with `# rule: R-<id> - why`.
- A `rejected` idea cites where it was rejected.
